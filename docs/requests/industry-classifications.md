# 資料需求：歷史產業分類（industry-classifications）

- 提出方：`stock-model-selection`
- 對象：`stock-data-center`
- 日期：2026-09-26
- 狀態：待 Data Center 評估

## 摘要

請提供一份有時間維度的產業分類：能查到每檔股票在 2020-01-02 以來任一天屬於哪個產業，以及這個分類從什麼時候起被公開知道。下市股票也要包含在內。

---

## 1. 為什麼今天的分類不夠

`/v1/stocks` 的 `industry` 是今天的分類，會原地更新，沒有歷史。實測有兩個問題：

1. **產業類別本身改過。**
   - 居家生活、數位雲端、綠能環保、運動休閒四類的指數，在 `indices` 裡都是 2023-07-03 才開始有資料。
   - 今天屬於這四類的股票，上市櫃合計 140 檔（居家生活 36、數位雲端 37、綠能環保 40、運動休閒 27）。它們在 2023-07-03 以前屬於別的類別。
   - 把今天的分類套用在 2023-07 以前的日期，等於使用當時還不存在的資訊。
2. **下市股票沒有分類。**
   - `/v1/stocks` 列出的股票中，有 56 檔的 `industry` 是 null，都是下市股票。
   - 例：2888 新光金（2025-07-24 下市）、2867 三商壽（2026-09-01 下市）下市前都是金融保險業，現在查不到。
   - 有些下市股票仍保留分類，例如 2809 京城銀、2823 凱基人壽，所以目前的行為不一致。

## 2. 用途

我們以「時點正確」（point-in-time，PIT）的方式建構歷史資料：每次選股決策只能使用在決策時點之前已公開的資訊。產業分類會用在：

| 用途 | 沒有歷史分類時的處理 |
|---|---|
| 從選股範圍排除金融保險業 | 用今天的分類；industry 為 null 的下市金融股認不出來 |
| 產業相對標準化，例如某檔股票的本益比在同產業中的排名 | 不做 |
| 回測報告的產業曝險，例如組合中半導體的比重 | 只能用今天的分類，數字會失真 |

我們的查詢方式：在某個決策時點 T（例如 `2024-07-11T04:00:00+08:00`），以 `information_as_of = T` 查詢，取決策日當天有效的分類。

## 3. 資料形狀

新增一個 observed 資料集，暫名 `industry-classifications`。每一列代表一檔股票在一個市場的一段分類期間，概念與 `/v1/stocks` 的 `listings` 相同。

| 欄位 | 說明 |
|---|---|
| `stock_id` | 股票代號，例如 `2330` |
| `market` | `sii` 或 `otc` |
| `source` | 資料來源代碼 |
| `industry_code` | 交易所的產業代碼，例如 `24` |
| `industry_name` | 當時的產業名稱，例如 `半導體業`；名稱可能改過，所以代碼與名稱都要 |
| `effective_from` | 分類生效日（含） |
| `effective_to` | 分類結束日（不含）；目前仍有效則為 null |
| `available_at` | 這個分類被公開的時點 |
| `recorded_at` | Data Center 記錄的時點 |
| `provenance` | `{fetch_id, raw_sha256}` |

- keys：`stock_id`、`market`、`source`、`effective_from`
- period：`effective_from`

範例（示意，不是真實資料）：

```text
stock_id  market  industry_name  effective_from  effective_to  available_at
XXXX      sii     其他電子業     2020-01-02      2023-07-03    （上市時點或保守值）
XXXX      sii     數位雲端       2023-07-03      null          （交易所公告時點）
```

## 4. PIT 規則

- 與其他 observed 資料集相同，支援 `information_as_of`、`knowledge_as_of`、`system_as_of`，回應帶 `pit` 區塊。
- `available_at` 是**公告**時點，不是生效時點。交易所通常會在生效前公告產業類別變更，所以兩者不同。
- 無法證明公告時間時，使用保守值，例如生效日 00:00 或記錄時點，並在資料集說明中寫明規則。做法比照 financial-reports 的保守日期。
- 查詢參數：
  - `start` / `end`：回傳與此區間重疊的分類期間。
  - 最好另外支援 `date=YYYY-MM-DD`：回傳當天有效的分類，做法比照 `/v1/stocks?date=`。
  - `stock_id` 可重複，限制與其他資料集相同。

## 5. 涵蓋範圍

- 期間：從 2020-01-02 開始，與 Data Center 其他資料集一致。
- 股票：與 `/v1/stocks` 相同的範圍（上市櫃普通股），**包含 2020-01-02 以來下市的股票**。
- 市場：上市、上櫃都要。上櫃轉上市的股票，每個市場各有自己的分類期間，因為兩個交易所的類別不完全相同（例如上櫃有農業科技業、文化創意業）。
- 分類體系：交易所官方的產業類別即可。不需要 GICS、次產業或產業鏈。

## 6. 可能的資料來源（請 Data Center 評估）

- **交易所的產業類別變更公告**：有公告日與生效日，最符合 PIT 的需求。
- **證交所每日收盤行情**：Data Center 已經在收 `twse_mi_index`。如果這份行情可以依產業類別查詢，每天都會列出各類別的股票，就能逐日重建上市股票的分類。上櫃的類股行情可能也有類似的來源。
- 我們沒有實際確認上述來源的歷史能回溯多遠，由 Data Center 判斷。

## 7. 驗收方式

拿到資料後，我們會做以下檢查：

1. 今天屬於居家生活、數位雲端、綠能環保、運動休閒的 140 檔股票，在 2023-07-03 以前都有別的分類。
2. 2888 新光金在 2025-07-24 以前是金融保險業；2867 三商壽在 2026-09-01 以前是金融保險業。
3. 2448（2021-01-06 下市）在 2020 年有分類。
4. 以 `date=2023-06-30` 查詢，各類別的股票數與當天對應產業指數的成分股數一致。
5. 所有目前仍有效的分類期間（`effective_to` 為 null），與 `/v1/stocks` 今天的 `industry` 完全相同。
6. 對任一時點 T，`information_as_of = T` 回傳的分類期間，`available_at` 都不晚於 T。

## 8. 在資料提供之前

- 我們的 v1 不做產業相對標準化。
- 排除金融保險業時，使用 `/v1/stocks` 今天的 `industry`。industry 為 null 的下市金融股是已知缺口。目前 Data Center 沒有下市股票的資料集歷史，所以這個缺口暫時不影響結果。
- 如果 Data Center 回補下市股票的資料集歷史，請同時提供本資料集，或至少補上下市股票在 `/v1/stocks` 的 `industry`。
